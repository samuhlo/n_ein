# n_ein 0.5.0-alpha.1

Esta alpha del canal **preview** reúne las mejoras de la PR #22: encontrar acciones, seguir procesos y sesiones, y ver qué parte del encargo está implementada y comprobada. Mantiene un agente y un modelo por encargo.

## Paleta de comandos

- **Alt+K** o `/nein:comandos` en Pi abre un buscador local con una explicación breve de cada acción. Busca por intención, nombre y descripción; solo ofrece comandos disponibles.
- En Claude, `/nein-comandos` abre su panel nativo. El foco y las teclas siguen perteneciendo al host.
- Las acciones con argumentos o que consumen modelo se preparan en el editor sin enviarse. El borrador se conserva.
- Abrir una revisión guardada se distingue de iniciar otra revisión con coste.

## Procesos y continuidad

- Pi puede ejecutar comandos largos y monitores con `nein_job`, sin consultas repetidas para esperar. `/nein:procesos` permite consultar resultados, logs y detenerlos.
- La ejecución conserva los hooks y permisos nativos de bash. Cada proceso tiene plazo explícito; los monitores limitan el ruido y la salida completa se guarda fuera del contexto. Cerrar o relevar la sesión detiene sus procesos propios.
- Las sesiones publican resúmenes pequeños de objetivo, avance, decisiones, bloqueos y siguiente paso. Se pueden buscar sin despertar otro modelo; fecha y estado antiguo permanecen visibles.
- El Panel amplía de cinco a cien las sesiones recientes del proyecto y las enriquece con sus resúmenes. No se recupera el bloqueo general por proyecto: pueden coexistir conversaciones independientes.
- Claude conserva sus tareas y avisos nativos.

## Encargo y evidencia

`nein work open`, la entrada «Encargo y evidencia» del Panel, `/nein:estado` en Pi y `/nein-estado` en Claude abren la vista local. **WORK.md sigue siendo la guía**; la web no crea otro TODO ni inicia inferencia.

Una comprobación ejecutada con `nein work check` conserva criterio, comando, resultado, log e identidad del código antes y después. Los cambios posteriores y los archivos nuevos invalidan su vigencia. Marcar una tarea como implementada no la convierte automáticamente en verificada. Un error o una identidad desconocida nunca se presentan como éxito vigente.

```sh
nein work sessions --query instalador
nein work status
nein work check --criterion T1 -- bun test
```

El alcance funcional de la prueba sigue necesitando revisión. La identidad no certifica archivos ignorados, servicios externos ni una aplicación desplegada desde otros bytes.

## Diseño hasta la comprobación visual

- Variantes HTML locales, comentarios sobre elementos y capturas PNG/JPEG; se conservan las alternativas y la dirección elegida.
- Elegir, implementar y comprobar visualmente son estados distintos. El visor prepara un encargo para llevarlo a la conversación; elegir una variante no ejecuta código.
- La implementación puede enlazar su preview local para compararla con el diseño. Si la aplicación rechaza iframes, se abre aparte.
- La aceptación visual exige describir lo observado y queda histórica cuando cambian el código o el HTML.
- `vision` y `prototype` se conectan con la skill `canvas`. Los archivos permanecen en `docs/design/<slug>/` y se pueden leer sin n_ein. Las historias largas de comentarios se conservan dentro de su límite específico.

## Contexto y correcciones de confianza

- `/nein:contexto` muestra el uso medido por Pi. El aviso de contexto es informativo y no delega ni cambia el modelo.
- `/nein:continuar` prepara una sesión nueva a partir de la guía, conservando autorización, modelo, esfuerzo y borrador. No inicia trabajo con otro modelo si el anterior no está disponible. En Claude se mantienen `/context` y `/compact` nativos.
- La skill `review` continúa las correcciones recuperables dentro del alcance, sin detenerse por haber consumido una sola ronda.
- p_reviewer distingue consumo desconocido, estimación parcial y completa; conserva la escritura de caché. No presenta esos importes como facturación.
- La CI prueba la misma versión de Claude declarada por el producto. Se elimina una carrera de la prueba de lectores sin cambiar los bloqueos del runtime.

## Qué no se activa

El ensayo de foco por riesgos no mejoró la detección de referencia: se conserva el revisor ordinario con **Sol 6.1 high**. El piloto de contexto tampoco justificó activar delegación: el código delegado pasó la aceptación, pero su recorrido agotó el plazo sin cerrar la guía. Ambos resultados y sus límites se conservan en `evals/results/`; no se promete ahorro ni una mejora general de detección.

## Actualización y datos

```sh
curl -fsSL https://samuhlo.github.io/n_ein/install.sh | bash -s -- --channel preview
```

Cierra las sesiones de n_ein antes de actualizar. Autenticación, preferencias y sesiones permanecen en su hogar nativo. Los registros de trabajo viven fuera del paquete; los diseños permanecen en el proyecto. Esta entrega no añade una migración del almacén de p_reviewer, que sigue en el esquema 5. Si se actualiza desde una versión anterior a 0.4, siguen aplicándose las precauciones de esa migración descritas en las [notas de 0.4.0-alpha.1](0.4.0-alpha.1.md).

Runtimes conservados: Pi 1.0.2, CodeGraph 1.6.1, Claude Code 2.1.302, Node 24.21.0 y Bun 1.3.14. Publicar la release no actualiza por sí solo ninguna instalación personal.

## Comprobaciones y alcance

La matriz de publicación verifica macOS arm64, Linux amd64, el mismo artefacto Linux instalado como usuario sin privilegios en Ubuntu y Arch, actualización/restore, manifiestos, hashes y procedencia. En aceptación se probaron Pi real con proveedor determinista, el plugin de Claude y el recorrido de diseño en Zen. Omarchy gráfico y las valoraciones humanas generales de detección siguen siendo comprobaciones separadas.
