# n_ein 0.2.0-alpha.1

Candidata a la primera alpha con instalación por curl y comprobaciones de distribución en macOS arm64, Ubuntu y Arch x86_64. **Pendiente de revisión y publicación.** La preview pública anterior sigue disponible.

## Cambios

- Integra la estética de n_ein en Claude Code y la nueva skill `readme` incorporadas después de preview.3.
- Node 24.21.0 y Bun 1.3.14 gestionados por versión y hash dentro de `~/.n_ein/runtimes`. Pi 1.0.2 y CodeGraph 1.6.1 permanecen fijados. No se depende de un Node global oculto en la máquina.
- Pi se instala en un proyecto privado dentro de su runtime: no busca ni modifica el package.json del proyecto padre.
- Instalador remoto en Go: selección SemVer por canal o versión exacta, checksum antes de extraer y ejecución del instalador del paquete seleccionado.
- Bootstrap `install.sh` pequeño, sin necesitar Go, Node, Bun, jq ni GitHub CLI para descargar el instalador. La instalación y el trabajo en proyectos requieren Git; ripgrep forma parte de los requisitos comprobados.
- Los paquetes se instalan solo con los archivos de su manifiesto. Se excluyen atributos extra de macOS de los tarballs.
- Matriz CI nativa macOS/Ubuntu, E2E desde hogar vacío, Arch con el mismo artefacto Linux y comparación de fuentes/archivos entre plataformas. Claude se prueba explícitamente con host 2.1.295; no hay inferencia pagada.

## Instalación después de publicar

Estos comandos necesitan que exista la release; no funcionan aún contra main público durante la revisión de la rama:

```sh
curl -fsSL https://raw.githubusercontent.com/samuhlo/n_ein/main/install.sh | bash -s -- --channel preview
```

Para fijar también el bootstrap y la versión del paquete:

```sh
curl -fsSL https://raw.githubusercontent.com/samuhlo/n_ein/v0.2.0-alpha.1/install.sh | bash -s -- --version 0.2.0-alpha.1
```

`--dry-run` consulta la release y muestra el destino, sin modificar el hogar. Sin canal ni versión se busca estable; mientras no exista una release estable se informa de ello, sin instalar una alpha silenciosamente. Se puede descargar `install.sh`, inspeccionarlo y ejecutarlo con los mismos argumentos.

La alpha utiliza el canal y el hogar **preview**. Sobre preview.3 se actualiza con backup; autenticación, sesiones, modelos y preferencias se conservan. Cierra las sesiones del canal antes de actualizar.

Para revisar un tarball candidato sin sustituir la instalación personal:

```sh
N_EIN_HOME="$HOME/.n_ein-alpha-review" N_EIN_LINK_DIR="$HOME/.n_ein-alpha-review/bin-entry" \
  ./n-ein-0.2.0-alpha.1-darwin-arm64/bin/nein-setup
N_EIN_HOME="$HOME/.n_ein-alpha-review" "$HOME/.n_ein-alpha-review/bin-entry/nein"
```

En Ubuntu/Arch se utiliza el tarball `linux-amd64`. El hogar separado necesita su propia autenticación; no se copian credenciales.

## Versiones y soporte

Secuencia: `0.2.0-alpha.1`, `alpha.2`, una candidata `rc.N` cuando proceda, y `0.2.0`. Durante alpha los arreglos incrementan alpha.N; un parche estable sería `0.2.1`. Se mantienen las releases preview antiguas y sus tags inmutables. Los metadatos `+hotfix.<sha>` identifican builds locales, sin intervenir en el orden de actualización.

Plataformas de esta entrega: macOS arm64 y Linux amd64. Arch se verifica automáticamente; la sesión interactiva en Omarchy queda como comprobación del usuario antes de publicar. No se declara soporte para macOS Intel, Linux ARM, Alpine o Windows en esta entrega.
