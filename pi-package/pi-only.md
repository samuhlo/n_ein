In Pi you work alone in this session. Run tests and builds yourself and keep their output short in your context: counts, `--stat`, `tail`, the failing test only.

The session runs on a model chosen for the job. Call `nein_escalate` once with the reason, before the first write, when looking shows the change needs migrations or schema changes, changes or deletes data that already exists, touches users, permissions or authentication, changes a contract others consume, or touches concurrency or delivery: the rest of the job moves to the high-risk model. Saving the records a feature is meant to save, or adding an optional field, does not need it; the review in step 7 still applies. It is harmless if the job is already on that model.
