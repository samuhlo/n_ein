# Relevo Pi→Claude, primer corte

El comando `/handoff claude` se probó en una TUI real de Pi 0.87.1 dentro de un repositorio temporal con `WORK.md` y un cambio Git pendiente. Escribió el resumen en el hogar Pi aislado, cerró Pi y el lanzador invocó después un ejecutable Claude simulado en otro hogar. Ese ejecutable recibió el resumen como mensaje inicial, la voz de Ein y el catálogo de skills mediante un enlace al paquete único.

`bun run tests/handoff.ts` comprobó que el resumen conserva objetivo, decisiones, tareas hechas y pendientes, última petición, commit, archivos modificados y nuevos, y que marca la vigencia de las comprobaciones como desconocida hasta contrastar el diff. El test también comprueba que `waitForIdle()` ocurre antes de escribir la señal y pedir el cierre. `tests/handoff-launcher.sh` verifica que Claude no arranca antes de que Pi termine y que no hereda `PI_CODING_AGENT_DIR`.

`CLAUDE_CONFIG_DIR=~/.n_ein/dev/claude` quedó separado y `claude auth status --json` informó `loggedIn: false`. Pendiente: autenticar ese hogar, probar la sesión real de Claude, su carga efectiva de instrucciones/skills y la vuelta Claude→Pi. El ensayo no acredita todavía aislamiento completo de toda la configuración externa ni ausencia de escritores solapados ante procesos padre independientes.
